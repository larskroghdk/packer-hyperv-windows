## 🖥️ Desktop compatibility audit (2026-11-20)

Read Config, generated HCL2Spec, main registration, guest actions, restart logic, applicability/lifecycle, examples and tests in all four local sources at the commits above. No sibling source was modified. Client features use DISM identities MicrosoftWindowsPowerShellV2Root and NetFx3. Optimization supports Client builds from 14393; catalog applicability still controls each setting. Cleanup supports Client x64, safe staging roots and service/feature/pending-reboot checks. sysprep=true rejects Hyper-V, so it remains false.

Hardening includes win11-24h2 (26100), win11-25h2 (26200), win11-26h2 (26300), with edition-aware lifecycle checks. There is NO Windows 10 baseline. Windows 10 skips the plugin and uses a separately reported limited local policy stage. Complete baseline compliance is not claimed. Win11 post-update dry_run reports gate release.

The windows-software and custom windows-update sibling repositories are absent. No schema was invented. Inherited rgl/windows-update 0.18.4 handles online updates. A small bridge installs opt-in signed/hash-checked MSI packages and Microsoft VC++ runtime EXEs using fixed silent arguments. Empty arrays request no software. Reports explicitly identify this compatibility substitution.

Custom release downloads were unavailable in the original audit. Install-LocalPlugins compiles the audited source pins with their documented release-version override, installs via packer plugins install --path and records commit/dirty/hash evidence. This is not signed-release certification. Source/module access and Go are prerequisites. CI uses the same pins.

The inherited SYSTEM MSU bridge preserves operator prerequisite order and Packer restart boundaries. Update_limit is batch size, not pass count; timeout bounds total successful cycles. No unsupported report_path or offline update interface is configured. Manifest generation derives update evidence from final guest WUA and package records.
